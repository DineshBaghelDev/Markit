# Setup and integrations

## Application

One Next.js application lives at the repository root with the App Router under `src/app`. npm and package-lock.json are the dependency source of truth. Tailwind uses the configuration generated by the current Next.js CLI. shadcn uses the Base UI Nova preset and neutral semantic tokens.

Use `npx shadcn@latest add <component>` for additional components after checking the registry and documentation. Avoid installing unrelated libraries in advance.

## Convex

The local deployment has the campaign schema and a read-only `health:check` query. Generated files in `convex/_generated` are committed, and local backend state in `.convex` is ignored.

The supplied cloud project rejected the machine's current Convex identity. Local development is configured instead; the original cloud URL remains in ignored `.env`. A URL alone does not authorize schema/function deployment.

To use that cloud project, log in with an account that has access and run `npx convex dev --configure existing`. Ensure `CONVEX_DEPLOYMENT` contains a deployment selector, not a URL. Development scripts explicitly read `.env.local` so a conflicting inherited environment variable does not choose the wrong deployment.

No public campaign write functions are exposed yet. Define access behavior when implementing the campaign flow.

## OpenAI

`src/lib/server/openai.ts` creates the official SDK client lazily. It requires `OPENAI_API_KEY` only when called and uses bounded timeouts/retries. Set `OPENAI_MODEL` when implementing the model request. No paid model requests are made by the starter.

## Crustdata

`src/lib/server/crustdata.ts` implements the free account credits request using Bearer authentication and the documented `x-api-version: 2025-11-01` header. It validates the returned balance with Zod, disables response caching, and sets a timeout. Lead/company search will be added when the demo interaction is defined.

## Vercel

Import the repository as a Next.js project with the repository root as the root directory. No custom Vercel configuration is needed.

Use a cloud Convex deployment for hosting; the local backend URL is only for development. Set `NEXT_PUBLIC_CONVEX_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`, and `CRUSTDATA_API_KEY` in the Vercel project environment.

To deploy Convex as part of the build, provide a suitable `CONVEX_DEPLOY_KEY` and use `npx convex deploy --cmd "npm run build"` as the build command. Do not put a deploy key in a public variable or the repository.

No Vercel deployment has been created as part of this local setup.
